# ADR-004. Open Source или коммерческое ПО для целевого стека Fast Cargo

**Статус:** предложено к защите на архитектурном штабе холдинга.
**Контекст:** штаб требует обосновать выбор стека, в том числе преимущества Open Source перед коммерческим ПО. Ограничения: только РФ, 152-ФЗ (сертифицированные средства защиты для ИСПДн), компетенции команды Fast Cargo недостаточны, бюджет ≈ 92 млн ₽ CapEx.

## Решение
**Платформа — Open Source в managed-исполнении российского провайдера, средства защиты — коммерческие сертифицированные.**

## Почему Open Source для платформы
1. **TCO.** Нет лицензий на ядро и на каждый узел при росте ×10, платим только за инфраструктуру. Экономия по сравнению с коммерческими аналогами — порядка 15–25 млн ₽ за 3 года.
2. **Нет vendor lock-in и санкционных рисков.** Стек одинаков у Yandex Cloud, VK Cloud, Cloud.ru и в ЦОД холдинга. Это стратегия выхода (exit strategy) для производственного департамента.
3. **Компетенции.** PostgreSQL, Kafka и ClickHouse — самые распространённые навыки на рынке, их проще нанять и проще передать от интегратора. Слабая сторона OSS — отсутствие вендорской поддержки. Её закрывают SLA managed-провайдера и договор с интегратором на первые 12 месяцев.
4. **Совместимость с коммерческими версиями.** Если ИБ потребует сертифицированный компонент (Postgres Pro Certified, Arenadata), переход проходит без переписывания приложений: API и протоколы совпадают.

## Последствия
- (+) Масштабирование ×10 без роста лицензионных платежей, переносимость между площадками.
- (−) Нужен сильный Platform/SRE (заложен в OpEx) и интегратор (заложен в CapEx). Ответственность за обновления лежит на нас и провайдере.
- (−) Сертифицированные СЗИ/СКЗИ — обязательная коммерческая статья расходов, она учтена в бюджете.
